# 共通辞書と授業別の用語辞書

## いつも使う共通辞書

- 共通の25語と日常表現12件をアプリに用意し、授業別辞書と同時に使います。「声色／こわいろ」「ローカルLLM／ローカルエルエルエム」などを含みます。
- 「設定 → 用語辞書」で、共通・授業別の一覧と読み方を確認できます。授業別の選択を「共通辞書のみ」にすると、個別の授業辞書だけが外れます。
- 同じ言葉・別名が重なる場合は授業別辞書を優先します。共通側の該当項目を実行時の合成辞書から外し、どちらのファイルも書き換えません。
- 日常表現は音声認識の候補です。「大丈夫です」「なるほど」などの訳文を固定せず、「丈夫」を誤認識と決めつけた置換もしません。
- 共通用語は入力文補正・要約の手掛かりになります。字幕翻訳で固定する共通訳語は、声色・ローカルLLM・大規模言語モデル・人工知能・生成AI・プロンプトの6項目。ほかの一般語は文脈に合わせて翻訳します。
- 共通データは自作の一般語リストで、`Sources/CommonVocabulary.swift`にあります。外部コーパス・個人の会話・音声・教材を取り込んだものではなく、モデルの追加学習もしません。アプリ更新で共通リストを更新でき、個人の授業辞書は別に保持します。

0.1.18では、単独の「こわいろ」が「怖い色」と認識されたという報告に対応しています。日本語で前の字幕がなく、入力全体が「怖い色」（文末の句点等は許容）の場合に限り、「声色」を入力文のAI補正へ渡します。これは登録語を優先する個別の補正候補で、音だけから話者の意図を判定したものではありません。授業別辞書に一致する表記があればそちらを優先します。「怖い色を使う」などの文章、前の文がある場合、通常の翻訳や資料要約にはこの候補を追加しません。AI補正がオフの場合は認識原文を保持します。

## 保存先と更新

利用者の辞書は `~/Library/Application Support/Quillo/Glossaries/<id>.json` に保存します。選択IDは既存のアプリ識別子のUserDefaultsに保存します。配布アプリのリソースに入れないため、アプリ更新で消えません。教材本文、発表者メモ、教材名を含む辞書は個人データとして扱い、公開リポジトリにコミットしないでください。

「設定 → 用語辞書 → 辞書を追加・更新…」から読み込みます。同じIDなら原子的に更新し、その辞書を選択します。別資料には別IDを使います。「共通辞書のみ」で授業別の適用を外せます。現在はファイルで編集・追加する方式です。

## JSON形式

```json
{
  "id": "example-material",
  "name": "授業用語の例",
  "entries": [
    {
      "terms": {
        "ja": "試作",
        "en": "prototype",
        "zh-Hans": "原型",
        "zh-Hant": "原型"
      },
      "aliases": { "ja": ["しさく"] }
    }
  ]
}
```

`aliases`は省略できます。対応言語はja、en、zh-Hans、zh-Hant。各項目に2言語以上が必要です。1辞書100項目、ファイル256KB、名称と各語80文字まで。同じ言語の同じ語を異なる項目に登録するとエラーになります。IDは英数字・ハイフン・アンダースコアのみ、80文字以内です。改行や制御文字は用語に入れられません。

読み方は別名として登録できます。誤変換された一般語を無差別に別名登録すると誤置換につながるため避けてください。1文字の語・記号は文中の用語置換から除外します。日本語は一致位置で長い複合語を優先し、英語は単語の途中に一致させません。活用形や未知の表記は自動で追加しません。

## 適用方法と制約

- 音声認識：正規語を優先し、別名も含めて最大100個のcontextualStringsを認識要求へ設定します。共通用に最大40枠を確保し、残りを授業別へ割り当て、空きがあればどちらも追加します。全登録語が同時に認識候補に入るとは限りません。再認識の区切りにも再設定します。これは認識候補であり、カスタム音響モデルや発音モデルの学習ではありません。[Appleの説明](https://developer.apple.com/documentation/speech/sfspeechrecognitionrequest/contextualstrings)
- 字幕：macOS 15 TranslationSessionには辞書引数がありません。一致語を一時識別子へ置換して1回翻訳し、登録訳語へ戻します。識別子の欠落・重複・改変があれば原文で再翻訳し、不明な識別子を画面へ出しません。単語全体が完全一致する入力は辞書から直接返します。原文ログは変更しません。文法・語形・冠詞・多義語は不自然になる場合があり、文章全体の精度を保証する仕組みではありません。
- 入力文補正：原文に一致した用語だけをAIへ渡します。登録した読み仮名から正規語への変更は文字数・差分比較で正規化して評価し、無関係な変更は通常どおり検査します。
- 要約：選択範囲に存在した語だけを、訳語対応のJSONとしてローカルAIへ渡します。辞書の語を理由に新しい内容を追加しないよう指示します。AIが原語の表記を残した場合は、入力で一致していた用語に限って登録訳語へ補正します。すでに正しい訳語になっている箇所は保護します。それ以外の言い換えが残る場合もあります。
- 辞書更新：進行中の古い字幕・要約を世代で除外し、現在の文章を更新します。要約キャッシュは無効化し、入力キーにも用語情報を含めます。画面共有や準備済みTranslationSessionを作り直しません。UIでは認識中の辞書変更を無効にし、認識候補が次回開始から確実に適用されるようにします。

## 確認

`zsh test.sh`に辞書の保存・再読込、検証、複合語優先、英語の単語境界、別名、繁体字、用語保持に失敗した際の通常翻訳、字幕の古い結果除外、要約キャッシュ変更のテストを含みます。`build/glossary-tests --live`はローカルOllamaを用いて架空の短文を英語・繁体字へ要約します。マイクや画面共有は使いません。ライブの音声認識精度は実際の教室で確認してください。
