# 内部の仕組み

[トップページへ](../README.md) ／ [開発・更新の引き継ぎ](MAINTENANCE.md)

## 音声字幕

- 日本語・英語のApple Speech端末内認識を使用。マイクの取り込みは停止するまで継続し、発話後の約0.8秒の無音、または最長約55秒で認識リクエストだけ更新。終了結果を最長1.5秒待つ間も音声はメモリ内へ保持して次のリクエストへ渡す。中国語のマイク開始は権限要求前に拒否する。
- 話す言語と現在の字幕原文の言語を分離。文字入力は4言語を維持し、マイク開始時は日英の話す言語へ戻す。資料の原文言語は独立し、表示先だけ字幕と共有する。
- 途中の認識結果を原文字幕へ即時反映。発話の区切りや翻訳完了を待たない。
- 任意のAI補正（`captionCorrection.v1`、初期値オフ）は約0.45秒安定した途中入力または確定した入力を同じ言語で最小限修正。認識変更時に待機時間を更新し、同じ文字の通知では延長しない。原文・初回訳を待たせず、採用した原文へ置換してApple Translationへ再投入する。原文のみ・同じ入出力言語でも働く。4秒の期限、同時1件＋最新待機1件、発話ID・認識の版・世代・直前三発話の検査を維持。
- 補正用コンテキストは4096、起動・補正オン・マイク開始時に取得済みモデルを先に読み込む。文字の差分が1文字以内なら二度目のAI照合を省略し、大きな変更は照合を維持。数字・条件・用語・変更量は全件確認するが、正確さの保証ではない。
- 生の認識結果と表示原文を分け、同じ認識の再通知で補正を戻さない。原文の補正・復帰は翻訳の版を進め、前の原文に対する翻訳を拒否する。訳し直す間は該当する訳だけを消し、原文・訳とも同じ発話の枠へ置換。オン／オフや表示モードでマイク・翻訳セッションを再起動しない。
- 状態表示と比較は入力文が対象。補正前の原文をメモリ上のログに保持し、手動保存時は明示する。自動保存はしない。ログは終了時に消える。
- 数字・長さ・言語・既存の登録用語・否定や条件・編集量を検査し、変更した候補をローカルAIで再確認する。短い断片の内容変更や推測による補完は拒否する。チェックは完全な認識精度・意味同一性の保証ではない。不採用・未準備・時間切れなら入力をそのまま使う。
- Apple Translationで翻訳。翻訳は同時に1件、開始間隔は最短180ミリ秒。認識・翻訳の処理時間は別。
- 言語変更・再試行ごとに固有IDのSwiftUIホストを生成し、キャンセル済みの翻訳セッションを再利用しない。セッションIDと世代番号で古い処理を除外。
- 文字入力の簡体字⇄繁体字はFoundationの文字変換を使い、Apple Translationの非対応ペアへ送らない。同じ言語は原文表示。中国語の文字入力・翻訳結果は選択した字体に揃える。
- 選択言語の端末内音声認識データを開始前とアプリ復帰時に確認。未準備なら設定手順を表示し、クラウド認識へ切り替えない。
- 同一発話の待機中の結果を最新にまとめ、現在の発話を優先する。
- 前の発話の結果はログだけを更新し、現在の字幕を上書きしない。
- 表示モードの変更ではマイク・翻訳セッション・現在の原文を維持する。
- 消去・言語変更・新しい入力セッションでは、古い処理結果を表示へ戻さない。
- `SpeechPhraseSegmenter`は一つの認識タスクの累積原文を話の区切りごとに別の字幕IDへ分ける。音声時刻が有効なら0.8秒の間または8秒の連続発話で区切る。途中認識に0.011秒刻みの仮の時刻しかない場合は結果の到着間隔・安定した原文の接頭辞を使う。候補の位置をNLTokenizerの単語・Unicodeの文字境界で確認し、「大→大丈夫」のような途中更新を単語内で分割しない。音声時刻がない場合は5文字未満の短い冒頭と日本語の助詞・語尾の続きを保持し、次の単語の先頭が前の結果に含まれていたら境界を単語の頭へ戻す。認識エンジンは再起動せず、新しい区切りだけを翻訳キューへ渡す。
- 全文はメモリのログに保持。字幕パネルは現在の一文と設定に応じて直前の0〜2文を表示し、文字列を省略記号で切り詰めない。
- 4言語の標準の読みやすさ表示は表示のみを変更。`SentenceCaptionReading`は最初の結果・確定結果を即時反映し、途中結果を最短650ms間隔で集約。待機中は最新1件だけを保持し、固定した期限を更新のたびに延長しない。
- 出力言語に合わせた`NLTokenizer`の文単位と`SentenceCaptionLayout`で最新の一文を切り出し、表示文字サイズを自動調整。原文・翻訳それぞれに直前二文を保持し、時間では消さず新しい文で入れ替える。途中結果の修正を履歴へ追加せず、文末記号のない発話・意図的な繰り返しも保持。過大な一文は句・単語の境界から末尾を表示。日本語・中国語は空白を前提にせず「，；：」等や単語境界を使い、「。！？」と閉じ括弧・引用符にも対応。全文ログ・訳語は変更しない。
- 読みやすさ表示は対象言語の標準に固定し、旧`readableEnglish.v1`設定は参照しない。原文のみ／翻訳のみ／両方の切替は翻訳セッション・マイクを保持。消去・言語変更では原文・翻訳の履歴を破棄。辞書変更では翻訳の表示用タイマーと持ち越しを破棄。直前二発話の識別子と空の枠も保持し、遅れて届いた翻訳は該当する履歴のみ修正する。現在の文は上書きしない。認識・翻訳の文位置が進んだときに実際に表示した現在文を履歴へ移し、同じ位置の途中修正では追加しない。
- 履歴設定`captionHistory.v1`は既存の外観設定と別に保存。初期値はオン・2文。オフ／1文／2文は表示と必要な高さだけを変え、内部の履歴記録・翻訳キュー・セッションは維持する。

PowerPointとの実測速度比較は行っていません。

## 資料要約

- ScreenCaptureKitでユーザーが選んだ画面を取得。
- 最大毎秒2フレーム。文字が350ミリ秒変わらないことを確認して処理。
- Vision OCRで選択範囲ごとに文字を抽出し、段組の読み順を自動整理。空の範囲も選択順の番号を保持し、番号をページ署名に含める。
- 範囲ごとのOCR文章をローカルOllamaの`qwen3.5:9b`へ順に渡し、要約と翻訳を実行。他範囲の文章は同じリクエストに混ぜない。番号はアプリで付け、一つのパネルに番号別で表示。途中結果・空範囲・失敗も範囲別に表示。
- 概要1文と重要点1〜3項目。小さいパネルでは概要1文へ短縮。
- 12 ptまでの自動縮小で収まらない場合は、より短い要約を再生成。
- 全範囲の入力合計はUTF-8で12,000バイトまで。超過時は切り捨てず、範囲を絞る案内を表示。
- 文章・言語・長さ・用語情報ごとに最大64件をメモリへキャッシュ。辞書変更時は無効化。
- 世代番号とキャンセルで、前のページや古い辞書による結果を除外。

## 通信と保存

- 要約・字幕補正の接続先は`127.0.0.1:11434`に固定。
- クラウドモデル、HTTPリダイレクト、プロキシ、クラウドへの自動切り替えを拒否。
- Ollamaが停止中の場合は、インストール済みアプリの起動を試みる。
- モデルを自動でダウンロードしない。
- 音声・画面画像・原文・要約は録音／録画として保存しない。
- 表示設定はUserDefaults、利用者の辞書はApplication Supportに保存。
- 字幕ログは明示的な「テキストで保存」でのみファイルへ出力。

## ビルドとテスト

- `zsh build.sh`：アプリのビルド。設定済みの固定署名を優先し、未設定時のみアドホック署名。
- `zsh test.sh`：字幕・表示・要約・辞書の回帰テスト。Visionを利用できるMac環境が必要。
- `build/glossary-tests --live`：Mac内のOllamaを使う用語付き要約テスト。
- 結果と未確認の条件は[確認記録](VALIDATION.md)に記載。

## 共通語と授業別辞書

`CommonVocabulary`の一般用語・日常表現を常時利用し、`GlossaryStore.effective`で個人の授業別辞書を重ねる。全言語の正規語・別名が衝突した共通項目は外し、授業別を優先する。保存ファイルには合成結果を書かない。認識は最大100件のうち最大40件を共通用に確保。入力補正・要約には一致した用語のみを渡し、原文補正の差分は既知の読み仮名を正規化して比較する。字幕翻訳は`translationGlossary`の限定した共通6語＋授業別を使用し、日常会話を固定訳にしない。
