# Quillo for Mac

授業中の発話を字幕にし、PowerPoint・Keynoteなどに重ねるMacアプリの試作です。ブラウザー、Webサーバー、アカウント、APIキーは不要です。

**Quillo（クイロ） — ことばを重ねて、授業をつなぐ。**

このMacでは「アプリケーション → Quillo」から開けます。Spotlightで「Quillo」と検索しても起動できます。開発を別のチャットで続ける場合は、リポジトリのURLと [開発・更新の引き継ぎ](docs/MAINTENANCE.md) を伝えてください。

## 動作環境

- Apple Silicon搭載Mac（M1以降）、macOS 15以降。
- マイク字幕には、macOSのマイク・音声認識の許可と、選択言語の端末内音声認識データが必要です。「システム設定 → キーボード → 音声入力」が無効な場合は、有効化の案内を確認してください。
- 翻訳はAppleのTranslationフレームワークを使用します。初回の言語データ取得にはインターネット接続が必要です。対応言語は日本語・英語・中国語（簡体字／繁体字）です。繁体字は「中文（繁體字）」として独立して選べます。音声入力の地域は台湾、翻訳とOCRは繁体字として指定します。
- 音声認識は端末内で実行する設定に限定しています。利用できない場合は停止して案内し、クラウド認識に自動で切り替えません。
- 資料の「要約」には、Mac内で動くOllamaと取得済みの `qwen3.5:9b` を使用します。このMacには両方導入済みです。要約はクラウドの利用回数枠やAPIキーを使いません。音声字幕の翻訳はOllamaなしでもApple Translationで利用できます。

## 授業で使う

アプリを開くと「授業」が表示されます。普段使う操作はここにまとめています。

1. 「使う言語」で、話す・資料の言語と、表示する言語を選びます。
2. 「音声字幕」の「話して字幕を出す」でマイク字幕を開始します。初回は「翻訳を準備」で必要な言語データを取得します。
3. 字幕に出す内容は「原文のみ」「翻訳のみ」「原文 ＋ 翻訳」から選びます。話している途中でもマイクを止めずに切り替えられます。「原文のみ」から翻訳表示へ戻すと、現在の文章から翻訳を再開します。翻訳待ちのとき、翻訳のみでは原文を出しません。
4. 「資料の要約」では、資料の画面と範囲を選んで要点を表示します。
5. 見た目を変える場合は「表示設定」へ進み、「音声字幕」「資料の要約」のどちらを調整するか選びます。

字幕・要約の背景をドラッグして移動し、右下のつまみでサイズを変えられます。「位置を固定」をオンにすると、その下の資料を操作できます。

「表示設定 → 動作確認・字幕ログ」を開くと、字幕デモ、要約デモ、文字入力による確認、字幕ログの保存ができます。デモはマイクを使用しません。要約デモはサンプル資料を使い、他のアプリの画面共有を必要としません。

## 資料の要約を別パネルで読む

「授業 → 資料の要約」から使います。選択範囲の概要と重要点を、表示する言語で短くまとめます。全文訳・ページ送り・スクロールは使いません。

1. 「資料の画面を選ぶ」を押し、Mac標準の画面でCanvaやPowerPointなどのウィンドウを選びます。「共有」はこのアプリで読む許可であり、インターネット配信ではありません。
2. プレビューで資料の部分をドラッグして囲み、「この範囲で要約」を押します。離れた複数の範囲も選べます。「範囲を変更」で囲み直せます。
3. 要約は操作ボタンのない、字幕と同様の小さな窓に表示します。「スライド要約・翻訳」を表示言語の大きな見出しで示し、音声字幕と区別します（同じ言語なら「スライド要約」）。概要1文と要点1〜3項目、小さい窓では概要1文だけにまとめます。背景で移動、右下でサイズ変更ができ、位置と大きさは次回も引き継ぎます。
4. 「表示設定 → 資料の要約」で、文字サイズの上限、背景色、背景の濃さ、位置固定を調整します。文字は12 ptまで自動縮小し、それでも収まらない場合は短く要約し直します。文章の途中を切り捨てません。
5. 言語は音声字幕と共通で、日本語・英語・簡体字・繁体字を選べます。同じ言語なら、その言語で要約します。音声字幕を「原文のみ」にしても要約の言語は変わりません。
6. 読み順の手動設定はありません。文字の配置から段組を自動整理した上で、AIへ渡します。複雑な段組の判定やOCRが誤る場合はあります。
7. スライドが変わると自動更新します。「要約し直す」でキャッシュを使わず作り直せます。遅れて戻った前のページの結果は表示しません。
8. 「要約を隠す」は表示だけを消します。「停止」は資料の読み取りも終了します。表示・位置固定はメニューバーの吹き出しからも切り替えられます。

範囲は同じ共有対象である間、画像に対する割合で保持します。資料の構成やブラウザーのツールバーの高さが変わった場合は囲み直してください。対象・言語の変更や停止で範囲をリセットし、終了後には保存しません。

学生へ資料と要約を見せる場合は、パネルと資料を並べた**画面全体**を共有・投影してください。資料ウィンドウ単体の共有には別パネルは入りません。パネルは別ディスプレイへも移動できます。ディスプレイ全体を読み取る場合は、要約パネルを選択範囲の外へ置いてください。自身のパネルは読み取りから除きますが、その下に隠れた文字も読めなくなります。

### 要約の仕組みと限界

選択範囲のOCR文章を、Mac内の `qwen3.5:9b` へ渡して要約と翻訳をまとめて行います。取得したQwen3.5 9B（このMacでは約7.6GBのMLXモデル）は、7例の架空教材を使い既存のQwen3 4B・Gemma4 E2Bと比較して選びました。結果と限界は [MODEL-EVALUATION.md](MODEL-EVALUATION.md) に記載しています。図や写真そのものはAIへ渡さず、読み取った文字だけを使います。要約は細部を省き、AIによる誤りもあり得るため、数式・条件・用語などを厳密に確認するときは元の資料を確認してください。

接続先は `127.0.0.1:11434` に固定し、クラウドモデル・HTTP転送・プロキシを使用しません。アプリがモデルを自動取得したり、クラウドへ切り替えたりすることはありません。Ollamaが停止している場合はインストール済みのOllamaを起動し、利用できないときはエラーを表示します。

同じ文章・言語・長さの要約はアプリ起動中のメモリに最大64件保持し、毎フレームの要約は避けます。初回のモデル読み込みやMacの負荷によって待ち時間が増えます。入力はUTF-8で12,000バイトまでとし、超過時は勝手に切り捨てず、範囲を絞る案内を表示します。AIの出力が条件に合わない場合も案内を表示します。

最大毎秒2フレーム、文字が350ミリ秒変わらないことを確認して処理します。OCR・AI自体の処理時間は別にかかります。音声や画面の録画、画像保存は行いません。画像・原文・要約キャッシュはメモリで扱い、アプリ終了時に破棄します。位置・サイズ・文字サイズ・背景色・濃さは設定として保存します。読み順の設定は保存しません。

参照元の [class-material-translator](https://github.com/xhan21/class-material-translator) の別パネルと読み順処理を参考にしています。このMac版は画像OCRとローカルAIによる要約を使うため、原文の色やリスト階層は再現しません。

## 授業中は、ライブ更新

音声認識の途中結果を受け取るたびに、原文をすぐ更新します。発話の区切りや翻訳の完了、固定の表示時間を待ちません。翻訳も途中の文章から始め、続きに合わせて更新します。途中の認識や訳文は、後から言い回しが変わることがあります。

- 長い発話は、パネルに収まる最新の行へ自動で追従します。手動スクロールは不要です。原文と訳文にはそれぞれ表示領域を確保します。
- 原文と翻訳の全文は字幕ログに保持します。画面上では古い行が上へ流れて見えなくなります。長文を一度に文字入力した場合も末尾を表示するため、全文の確認には「テキストで保存」を使ってください。
- 翻訳中に認識が進むと、同じ発話の未処理の途中結果を最新の内容にまとめます。翻訳は同時に1件、開始間隔は最短180ミリ秒です。最初の翻訳はすぐに始めます。この数値は認識・翻訳に必要な処理時間を含みません。
- 翻訳結果は、同じ発話の途中結果であれば先に表示して「翻訳を更新中…」と示します。前の発話の翻訳が遅れて戻っても、新しい字幕を上書きしません。
- 現在の発話を優先して翻訳します。前の発話の最終翻訳が残っている場合は、ライブ翻訳の待ちがない間にログを完成させます。ログには未完了の訳を明記します。
- マイク停止後も最後の発話の翻訳を続けます。「消去」、言語変更、新しいマイク開始・デモ開始では以前の処理を表示に戻しません。ログの原文は残りますが、その時点で翻訳未完了の行は未完了のまま残ることがあります。
- 翻訳に失敗しても原文の更新を続けます。「翻訳を準備」で、現在のセッションの未完了の翻訳を再試行できます。

以前の「切り替えの速さ」「字幕を一時停止」と、順番待ちによる自動ページ送りは廃止しました。音声認識・翻訳エンジンは従来のMac内処理のままです。PowerPointとの実測速度比較は行っていません。

## 字幕の見た目

「表示設定 → 音声字幕」で調整します。幅・高さ・表示先は「パネルのサイズ・表示先」を開くと調整できます。

- パネルの幅・高さ：スライダーと上下ボタンで調整。表示した字幕の右下をドラッグしても変えられます。
- 「高さを字幕2行ずつに合わせる」：オンでは原文・翻訳それぞれ約2行分の高さにします。オフでは指定した高さを使います。右下のドラッグでサイズを変えると、この設定はオフになります。
- 原文／翻訳の文字サイズ：それぞれ14〜90 ptで独立して調整できます。「翻訳文のみ」に切り替えても設定したサイズを保ちます。
- 背景：深緑・黒・白のボタン、または「その他」の色選択を使います。「背景の濃さ」を0%にすると透明です。文字色は背景色に合わせて切り替わります。
- 「見た目を標準に戻す」で見た目を初期値に戻せます。各設定は次回の起動時にも引き継ぎます。

小さいパネルでは最新の行を表示し、省略記号や文字サイズの自動縮小は使いません。幅・高さ・表示モードを途中で変えても、全文データを保ち、新しい表示範囲に合わせて最新の行を組み直します。

## 発表中の操作

- 設定画面を閉じてもアプリは動作し続けます。Macのメニューバーの字幕アイコンからパネルを開けます。
- Control + Option + Command + K：字幕を表示／非表示。
- Control + Option + Command + L：字幕位置を固定／解除。
- 終了はメニューバーの「Quillo を終了」、またはCommand + Qです。
- 外部ディスプレイがある場合は「表示画面」で選びます。「画面下に戻す」で字幕を回収できます。
- 投影する画面には設定画面を置かないでください。画面全体をミラーリングすると設定画面も映ります。
- Zoom等では、字幕と資料を含む「画面全体」を共有してください。PowerPointのウィンドウだけを共有すると、別ウィンドウの字幕は含まれません。

## データの扱い

音声の録音ファイルは作りません。字幕ログは音声認識のセッションごとにメモリ内で保持し、途中結果で同じ行を更新します。原文を件数上限で削除せず、終了すると消えます。「テキストで保存」を押した場合だけファイルを作ります。字幕の表示モード・表示位置・幅と高さ・各文字サイズ・背景色と濃さはMacのユーザー設定に保存します。

音声認識・翻訳は誤りや遅延が生じます。デモ字幕はサンプル表示で、認識・翻訳の精度を示すものではありません。字幕を180文字に切り詰める制限はありません。約50秒ごとに音声認識を再開するため、その境界では短い途切れが生じる可能性があります。

## 開発用

`zsh build.sh` で `build/Quillo.app` を作成します。Xcode Command Line ToolsとmacOS 15対応SDKが必要です。外部ライブラリは不要です。このMacで試すためのアドホック署名です。公証済みの一般配布アプリではありません。

`Sources/` がアプリ本体です。`Tests/PlaybackTests.swift` は最新行のレイアウト・Unicode・翻訳待ちの集約・ライブ優先を検証します。`Tests/PlaybackIntegrationTests.swift` は実際のAppModelと翻訳処理ループを使い、認識途中の即時反映・途中翻訳・古い結果の排除・確定ログ・失敗後の継続・キャンセルを検証します。`Tests/SlideTests.swift` は実際のVision OCR、文字・図・訳文の重なり回避、余白不足時の保持と座標変換を検証します。`zsh test.sh` で一式を実行できます。OCRテストはMacのローカル機械学習サービスを利用できる環境が必要です。補助処理は `Tests/CoreTests.swift`、見た目の保存・読み込みは `Tests/AppearanceTests.swift` にあります。
